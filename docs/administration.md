# Спільні налаштування застосунку

Сторінка `#/administration` керує фільтрами, KPI, блоками дашборду, колонками таблиць, назвами довідників, оформленням і меню. Розділ «Розрахунок KPI» задає критерій успіху, частку корисної дії та коефіцієнт для кожної мети: дивіться [опис формули й перевірки](kpi-calculation.md). Персональні параметри та збережені вибірки користувачів залишаються окремими.

## Робота зі змінами

1. Увійдіть до облікового запису адміністратора та змініть потрібні поля.
2. Натисніть «Переглянути». Зміни діють лише у вашій вкладці; зверху з'явиться позначка чернетки.
3. Збереження та публікація доступні адміністратору. До створення першого облікового запису використовується адміністративний ключ.
4. «Зберегти чернетку» зберігає роботу на сервері без зміни поточного інтерфейсу.
5. «Опублікувати» застосовує налаштування для всіх сторінок. Відкриті вкладки перевіряють нові версії кожні 30 секунд і при поверненні до вкладки.
6. Розділ «Історія змін» дозволяє відновити попередню версію. Відновлення створює нову версію.

Застосунок перевіряє версію публікації та чернетки. Якщо інше вікно вже зберегло зміни, запит відхиляється без їх перезапису. Збережіть потрібний зміст своїх локальних правок, скасуйте локальні зміни та натисніть «Оновити», щоб завантажити актуальні налаштування.

## Підказки карток

У підрозділі **Підказки карток** можна вибрати відкриття через наведення або натискання, тільки натискання чи вимкнення деталізації. Для наведення задається затримка від 0 до 1500 мс; 0 означає відразу. Ширина вікна буває стандартною або широкою, з обмеженням за шириною екрана. На сенсорних пристроях використовується натискання. Enter або пробіл відкриває вікно з клавіатури, Escape закриває його.

Це параметри подання наявної деталізації. Налаштування її складу залежно від правил або фільтрів у цьому підрозділі відсутнє. Зміни можна переглянути у власній вкладці, зберегти як чернетку та опублікувати для всіх. До вашого редагування старі конфігурації зберігають попередній вигляд: наведення без затримки та стандартну ширину. Читання історичних версій не переписує їхній збережений JSON.

## Доступ і збереження

Розділ «Доступ» дозволяє створювати окремі облікові записи з ролями «Користувач» та «Адміністратор», вимикати доступ і змінювати паролі. Користувач переглядає дані й налаштовує власний дашборд; адміністратор також керує спільними налаштуваннями й обліковими записами. Після створення першого адміністратора для перегляду аналітики потрібен вхід. Особисті налаштування зберігаються на сервері: дивіться [облікові записи й персональні дашборди](user-accounts.md).

Будову входу й технічних журналів, а також майбутній перехід на корпоративні облікові записи описано в [інструкції для Keycloak, Active Directory та Entra ID](authentication-and-logging.md).

Окремий ключ `APP_ADMIN_TOKEN` задається через `.env` для первинного створення адміністратора й відновлення адміністративного доступу. Він не входить у публічну конфігурацію, історію або фронтенд. При ручному введенні у браузері ключ зберігається в `sessionStorage` на час сесії вкладки. Якщо немає ані ключа, ані облікових записів, адміністративні запити вимкнені. Ключ керування кешем не відкриває доступ до налаштувань.

Для локального перегляду ключ також записаний у `.local/app-admin-key.txt`; каталог виключений із Git і контексту Docker. Не передавайте ключ разом зі звітами.

Версії й чернетка зберігаються в окремому SQLite сховищі `/app/data/app_configuration.sqlite3`, у постійному Docker томі `app_configuration_data`. Звичайний перезапуск чи перебудова контейнерів зберігає налаштування. Видалення цього тому видалить історію. Для тестів шлях можна змінити через `APP_CONFIGURATION_DB`.

## Межі першої версії

Підписи довідників змінюють лише відображення; стабільні коди та значення фільтрів не змінюються. ББАК і батальйон у поточному ClickHouse адаптері використовують одну сутність; панель показує один організаційний вибір. Старі відмінні умови збережених вибірок залишаються видимими як активні позначки.

Деталізація мети вильотів і підсумки кафедр використовують повний KPI «Вильоти», а не обмежену таблицю останніх подій. Групування мет у загальні категорії та підключення джерел поки налаштовуються на сервері. Ролі розмежовують перегляд аналітики та адміністрування; індивідуальні обмеження видимих записів за підрозділом не налаштовані.
